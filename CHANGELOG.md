# Changelog

## v4.88 — Roles and Permissions, Slice 1: User Identity
Real login identity via `profiles` (keyed to `auth.users.id`, never email/name), admin-managed users (create, deactivate/reactivate, reset password, change email) with full audit trail, shared `alerts` center starting with tracker-ID-change alerts, and an Audit Log tab. See `docs/specs/slice-1-user-identity.md`.
- Fixed a CORS bug in admin-users: the Edge Function did not handle OPTIONS preflight requests, so every browser call to it (create user, reset password, deactivate, tracker ID, forced password change) silently failed with no error shown. Added CORS headers and OPTIONS handling; sb.invoke() now also resolves with a friendly error instead of an unhandled rejection on network failure.
- Fixed a pre-existing bug (predates v4.88) in loadAllData()'s "cache valid" fast path: it never fetched bug_report_statuses or contact_role_types (so the Feature Req/Bugs status dropdown/filter silently degraded to plain text on any load after the first), and restored technicians from a stale localStorage cache instead of fetching fresh (so deactivate/reactivate could take a long time to show up on a device with a valid cache). Both now always fetch fresh, like settings already did.
- Fixed Audit Log tab getting stuck on "Loading...": the app renders a separate Settings body for mobile and desktop views, both containing an element with id="audit-log-rows" if you've ever viewed Settings in both device modes in the same session. getElementById() always grabbed the first (possibly hidden) one, so the visible tab never updated. loadMoreAuditLog() now updates every matching element instead of just the first.

## v4.89 — Operational Audit Trail
Extended the audit trail to ~31 tables (work orders, hours entries, line items, tasks, customers, vendors, technicians, settings, and more) via one reusable generic trigger, replacing the old hand-written per-field triggers on day_review and line_items. Every table's audit rows now carry a resolved `context` (e.g. the linked work order's number) so a single free-text search finds related edits across tables. The Audit Log tab (Settings) gained search: free text, date range, module, and action filters. See `docs/specs/operational-audit-trail.md`. Excluded on purpose: `location_event` (214k+ raw GPS pings), `profiles`/`alerts` (already have dedicated named-action auditing), `user_roles` (retired).

## v4.90 — Audit trail delete snapshot + Undo on hours/parts rows
- audit_row_changes() now captures a full snapshot of a record's field values into the "deactivate" audit row (e.g. hours, cost, tech, descriptor) instead of an empty summary — Kevin's feedback that a deleted hours entry showed no "before" value.
- Work order screen: deleting an hours or parts entry no longer removes it immediately — it now shows struck-through/greyed in place with an undo (↺) button to restore it, for the current view. Reopening the work order still shows only active entries as normal.
- Fixed the undo button being effectively invisible: the greyed-out look used `opacity` on the whole row, which composites down and can't be overridden by a child element — the button was rendering, just nearly transparent. Switched to muted text color on the cells only, leaving the button at full opacity and colored to stand out.

## v4.91 — Rename "Locations" module to "Sites"
Full-sweep rename (not just navigation): the Locations module, its Settings tab and sub-sections (Location Manager, Location Entity Types, GPS geofence settings), and the Field Travel Log GPS-stop-tagging workflow (mobile and desktop) all now say "Site"/"Sites" instead of "Location(s)" — roughly 35 user-facing strings across index.html, app-core.js, field-travel-log.js, and app-tasks.js. No schema changes, no internal identifier renames (table/column names, function names, and element ids are untouched) — label-only, per spec. First step of docs/specs/wo-search-ftl-calendar-site-visits.md; WO number search, Clear filters, and the FTL monthly calendar are reviewed and ready to build next.

## v4.92 — Session-expiry fix, audit readability, WO search/calendar
- Fixed "Invalid session" on admin actions (deactivate/reactivate/reset password/email change/tid changes): sb.invoke() (used for every admin-users Edge Function call) never refreshed an expired access token, unlike sb.req() which already retries once after a refresh. Now matches that behavior.
- Audit Log: the delete "snapshot" now skips foreign-key id columns and "who" columns (raw UUIDs/emails aren't readable) — regular field updates (e.g. reassigning a tech) are untouched, still logged in full. The Old/New column also renders multi-field snapshots one field per line instead of a run-on string.
- Work order screen: added a WO number search (partial match, combines with existing filters) and a "Clear filters" button that resets every ribbon filter/search back to the fresh-load default (Live, All Modes, All WOs, searches empty).
- Field Travel Log: added a collapsed-by-default monthly calendar above the weekly view — tap to expand, tap any day to jump the week view to it, shows the currently displayed week highlighted, navigate between months. Weekly view and its paging are unchanged. Desktop only for now.

## v4.93 — Site travel allowance (step 1 of site visits and claims)
Sites now carry a travel allowance: `locations.travel_to_minutes` and `travel_from_minutes` (default 0, 0 to 480). Shown and editable inline on the site detail screen, and in the Add/Edit site panel, where new customer-type sites pre-fill 30 minutes each way. All logic is in the new `app-sites-travel.js` with four one-line hooks in app-core.js. Nothing uses the allowance yet (claim rules come in a later step). The one-time 30/30 backfill for existing customer sites is a separate script (`supabase/migrations/v4.93_site_travel_backfill.sql`) and has NOT been run. See `docs/specs/site-visits-and-claims.md`.

## v4.94 — Customer invoice generation, slice 1
New module `app-invoice-gen.js` (spec: `docs/specs/invoice-generation-workflow.md`). Customer Invoice Generation now starts a guided, resumable run: step 2 in-progress review (oldest first, Open / Mark Completed), step 3 scope pick (all or specific customers, untick to hold back), then Start run moves the selected work orders to Batch Invoice Process (`batch_invoice`) immediately. Run state lives in the new `invoice_runs` table (one active run at a time; migration `supabase/migrations/v4.94_invoice_runs.sql`, applied). Progress bar plus a batch counter (work orders and dollars in Batch Invoice Process) sit in the top ribbon. Run screen: edit work orders while the run is open, Drop (back to Completed, pre-export only), Export to Zed Axis (existing review/export flow), Cancel run (unexported return to Completed, exported stay), Finish run (once none remain in Batch Invoice Process). Work orders in Batch Invoice Process are locked for everyone except the person running the invoice (app-level lock). Steps 4–8, acceptance (10) and the rest come in later slices.
- Replaced three hardcoded status numbers with `system_key` lookups: multi-bill return (was 7) in `runExport`, Truck Stock work order status (was 10), and the DWO Excel import `statusMap`. Statuses are found by key or category, never by number.
- `initInvoicingPanel` moved from app-core.js to app-invoice-gen.js (old copy commented out).

## v4.95 — Customer invoice generation, slice 2
Steps 4–6 of the run are now information-only check screens (never blocking, each with a shortcut and Refresh): vendor invoices last imported (latest active `vendor_import_history`), billable time entered through (latest billable hours entry date, plus last edit time), and days accepted through (day before the oldest worked day that is not `accepted`; `submitted` does not count) with the list of unaccepted worked days. Runs now start at step 4, save the step on Next/Previous, and Resume returns to the saved step. The entry screen shows last run exported (latest `invoice_runs.exported_at`, saved when the Zed export completes), ready-to-bill count and dollar total, and the safe-to-invoice cutoff (oldest of vendor import, billable time, days accepted, last run). No schema change. Steps 7–8 and acceptance come in later slices.

## v4.97 — Customer invoice generation, slice 4 (Zed export acceptance)
- **Acceptance (step 10):** after a Zed export the run lands on a checklist of its exported work orders (WO, customer, amount). Tick the ones verified in QBO and Accept ticked, or Accept all exported. Accepted work orders move from Batch Invoice Process to Invoiced (found by `system_key`); unticked ones stay and keep showing in the batch counter. Also available from the Work Orders list: select work orders in Batch Invoice Process and use **Accept Invoiced** in the batch bar. The run auto-finishes once every work order in it is accepted or returned.
- **Multi-bill:** a multi-bill work order now stays in Batch Invoice Process after export like any other (suffix count not bumped at export). At acceptance one prompt asks whether to return the multi-bill work orders to In Progress (billing suffix +1, export fields cleared) or mark them Invoiced as final. The old return-at-export code in `runExport` is commented out with a MOVED TO note; the new logic is `invAcceptWOs` in app-invoice-gen.js.
- Setup warning now also checks that the `invoiced` status exists.

## v4.98 — Invoice run reminder on the Daily Dashboard
Admin Daily Dashboard now shows a reminder card whenever an invoice run is unfinished (spec section 3d). ## v4.99 — PO Tracker module
New module `app-po-tracker.js` (spec: `docs/specs/dwo-spec-2026-10-05-po-tracker.md`). New sidebar panel (admin only) for tracking customer-issued purchase orders separately from the invoice-generation flow.
- **Schema** (`supabase/migrations/v4.99_po_tracker.sql`): `purchase_orders` (dollar-tracked or standing/time-based, lifecycle status Created → In Progress → Completed → Cancelled, admin-only RLS, audited), `purchase_order_customers` (many-to-many account assignment — a PO can draw against a single shared pool across more than one DWO customer record), `po_change_orders` (unlimited, editable/deletable change orders; deletion is a soft `active=false` so it's captured by the existing generic audit trigger). New `work_orders.purchase_order_id` column links a WO to a tracked PO. Two views — `po_ledger` and `po_wo_breakdown` — compute live billed/pending totals per PO from existing `line_items`, `hours_entries`, and `quoted_invoices`, gated on `work_orders.status = 12` (Invoiced).
- **Dollar-tracked POs:** original amount + change orders = current amount; live Billed/Pending (traceable to the work orders driving the pending total)/Remaining $/Remaining %; per-PO warning threshold ($ remaining or % consumed), with a system-wide default in Settings → Billing.
- **Standing/time-based POs:** no dollar amount; optional expiration date with its own configurable warning lead time (system-wide default in Settings).
- **Locking:** a new PO can optionally be locked to a work order created in the same flow (one-to-one). A locked work order cannot be cancelled (`setWOStatus`, single and batch) until the PO is untied first.
- **Work order PO field:** now a toggle between free text (unchanged, for untracked reference numbers) and a picker (select a tracked PO; field locks against free-text edits while a tracked PO is selected).
- **Dashboard:** new "PO Warnings" card lists POs at or past their dollar/expiration threshold (warn-only, never blocks time entry).
- Settings → Billing gained three new keys: default PO warning mode/value and default PO expiration warning lead time.
- **UI fixes (same build, before first use):** New/Edit PO and the PO picker are now full-screen (`screen-po-form`, `screen-po-picker`, same `pushScreen`/`goBack` pattern as the work order form) instead of bottom sheets. Fixed account/lock checkboxes stretching full-width (new `.po-acct-chk`/`.po-lock-chk` CSS, scoped like the existing desktop-grid checkbox rule). PO list, dashboard PO Warnings card, and the PO picker now use a bordered/structured `.po-grid-table` instead of the plain `dt-table` styling. Multiple customers on one PO now stack one per line (`poCustomerStackHtml`) instead of a comma-joined string.
