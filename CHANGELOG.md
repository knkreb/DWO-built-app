# Changelog

## v4.88 — Roles and Permissions, Slice 1: User Identity
Real login identity via `profiles` (keyed to `auth.users.id`, never email/name), admin-managed users (create, deactivate/reactivate, reset password, change email) with full audit trail, shared `alerts` center starting with tracker-ID-change alerts, and an Audit Log tab. See `docs/specs/slice-1-user-identity.md`.
- Fixed a CORS bug in admin-users: the Edge Function did not handle OPTIONS preflight requests, so every browser call to it (create user, reset password, deactivate, tracker ID, forced password change) silently failed with no error shown. Added CORS headers and OPTIONS handling; sb.invoke() now also resolves with a friendly error instead of an unhandled rejection on network failure.
- Fixed a pre-existing bug (predates v4.88) in loadAllData()'s "cache valid" fast path: it never fetched bug_report_statuses or contact_role_types (so the Feature Req/Bugs status dropdown/filter silently degraded to plain text on any load after the first), and restored technicians from a stale localStorage cache instead of fetching fresh (so deactivate/reactivate could take a long time to show up on a device with a valid cache). Both now always fetch fresh, like settings already did.
- Fixed Audit Log tab getting stuck on "Loading...": the app renders a separate Settings body for mobile and desktop views, both containing an element with id="audit-log-rows" if you've ever viewed Settings in both device modes in the same session. getElementById() always grabbed the first (possibly hidden) one, so the visible tab never updated. loadMoreAuditLog() now updates every matching element instead of just the first.

## v4.89 — Operational Audit Trail
Extended the audit trail to ~31 tables (work orders, hours entries, line items, tasks, customers, vendors, technicians, settings, and more) via one reusable generic trigger, replacing the old hand-written per-field triggers on day_review and line_items. Every table's audit rows now carry a resolved `context` (e.g. the linked work order's number) so a single free-text search finds related edits across tables. The Audit Log tab (Settings) gained search: free text, date range, module, and action filters. See `docs/specs/operational-audit-trail.md`. Excluded on purpose: `location_event` (214k+ raw GPS pings), `profiles`/`alerts` (already have dedicated named-action auditing), `user_roles` (retired).

## v4.90 — Audit trail delete snapshot + Undo on hours/parts rows
- audit_row_changes() now captures a full snapshot of a record's field values into the "deactivate" audit row (e.g. hours, cost, tech, descriptor) instead of an empty summary — Kevin's feedback that a deleted hours entry showed no "before" value.
- Work order screen: deleting an hours or parts entry no longer removes it immediately — it now shows struck-through/greyed in place with an undo (↺) button to restore it, for the current view. Reopening the work order still shows only active entries as normal.
- Fixed the undo button being effectively invisible: the greyed-out look used `opacity` on the whole row, which composites down and can't be overridden by a child element — the button was rendering, just nearly transparent. Switched to muted text color on the cells only, leaving the button at full opacity and colored to stand out.

## v4.99 — PO Tracker module
New module `app-po-tracker.js` (spec: `docs/specs/dwo-spec-2026-10-05-po-tracker.md`). New sidebar panel (admin only) for tracking customer-issued purchase orders separately from the invoice-generation flow.
- **Schema** (`supabase/migrations/v4.99_po_tracker.sql`): `purchase_orders` (dollar-tracked or standing/time-based, lifecycle status Created → In Progress → Completed → Cancelled, admin-only RLS, audited), `purchase_order_customers` (many-to-many account assignment — a PO can draw against a single shared pool across more than one DWO customer record), `po_change_orders` (unlimited, editable/deletable change orders; deletion is a soft `active=false` so it's captured by the existing generic audit trigger). New `work_orders.purchase_order_id` column links a WO to a tracked PO. Two views — `po_ledger` and `po_wo_breakdown` — compute live billed/pending totals per PO from existing `line_items`, `hours_entries`, and `quoted_invoices`, gated on `work_orders.status = 12` (Invoiced).
- **Dollar-tracked POs:** original amount + change orders = current amount; live Billed/Pending (traceable to the work orders driving the pending total)/Remaining $/Remaining %; per-PO warning threshold ($ remaining or % consumed), with a system-wide default in Settings → Billing.
- **Standing/time-based POs:** no dollar amount; optional expiration date with its own configurable warning lead time (system-wide default in Settings).
- **Locking:** a new PO can optionally be locked to a work order created in the same flow (one-to-one). A locked work order cannot be cancelled (`setWOStatus`, single and batch) until the PO is untied first.
- **Work order PO field:** now a toggle between free text (unchanged, for untracked reference numbers) and a picker (select a tracked PO; field locks against free-text edits while a tracked PO is selected).
- **Dashboard:** new "PO Warnings" card lists POs at or past their dollar/expiration threshold (warn-only, never blocks time entry).
- Settings → Billing gained three new keys: default PO warning mode/value and default PO expiration warning lead time.
- **UI fixes (same build, before first use):** New/Edit PO and the PO picker are now full-screen (`screen-po-form`, `screen-po-picker`, same `pushScreen`/`goBack` pattern as the work order form) instead of bottom sheets. Fixed account/lock checkboxes stretching full-width (new `.po-acct-chk`/`.po-lock-chk` CSS, scoped like the existing desktop-grid checkbox rule). PO list, dashboard PO Warnings card, and the PO picker now use a bordered/structured `.po-grid-table` instead of the plain `dt-table` styling. Multiple customers on one PO now stack one per line (`poCustomerStackHtml`) instead of a comma-joined string.
